# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Security

- `body-parser` 2.4.0 and `multer` 2.5.0 fix two high-severity denial-of-service advisories (GHSA-27r3-jxmh-p828, GHSA-q7qp-rjg7-q26m); `multer` is set through `pnpm.overrides` because `@nestjs/platform-express` pins 2.4.0.
- `/mcp` rejects JSON-RPC batches with 400, which let a single request run any number of tool calls past the rate limits.
- `/mcp` rejects a present `Origin` header whose host is not `PUBLIC_URL`'s, so websites can't make their visitors' browsers call the tools.
- Every response sets `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` and a strict Content Security Policy, and no longer sends `X-Powered-By`.
- `read_passages` ids are capped at 100 characters, and JSON request bodies at 16 KB.
- Swagger UI at `/docs` is off when `NODE_ENV` is `production`.
- CI runs `pnpm audit --prod`, and Dependabot checks npm and GitHub Actions updates weekly.

### Changed

- `read_passages` labels `hbo` originals Ancient Hebrew instead of Biblical Hebrew, since Pirkei Avot is Mishnaic Hebrew.
- `typescript-eslint` bumped to 8.72.0 and `knip` to 6.43.0.
- `@nestjs/common`, `@nestjs/core` and `@nestjs/platform-express` bumped to 12.2.0 together, since none of them works with the others on 12.1.3; Dependabot now groups `@nestjs/*` updates into one pull request.
- Dependencies bumped to their latest versions, among them `@nestjs/*` 12.1.3, `@modelcontextprotocol/server` 2.3.1, `express` 5.3.0 and `zod` 4.6.7, and CI's `actions/checkout`, `actions/setup-node` and `pnpm/action-setup`. TypeScript stays on 6.0.3, and `@types/node` stays on 24.x to match the Node 24 runtime; Dependabot now ignores its major updates.
- `pnpm readings:draft` now lists the 釋文 notes it skips: notes on characters missing from the polyphone list whose reading differs from pinyin-pro's. Reviewing that list added 23 characters, among them 适 kuò, 應 yìng, 召 shào in names, 妻 qì as a verb and 亞 yà, so 57 more Analects and 13 more Laozi occurrences now take a reading from the readings files. Four occurrences the notes don't settle were reviewed by hand.
- `get_concept` builds each key passage snippet around the phrase that makes it key, imported from the Wisdom Context Window's `quote` field into a new `concept_passages.quote` column, instead of cutting at the first 40 words. It starts a few words before the phrase, and falls back to the passage opening when the phrase isn't in the text.
- `list_concepts` and `get_concept` show the original term after the name without an extra pair of parentheses, and `get_concept` no longer wraps snippets in quotation marks.
- The `/wisdom` skill gives the transcription after a quote without a label.
- macOS `.DS_Store` files are now gitignored.
- The Swagger document now takes its version from `package.json` instead of a hard-coded `0.1.0`.
- Exports used only inside their own module are no longer exported.
- Bhagavad Gita references are now the verse range each Arnold passage renders (e.g. 18.64-65) instead of a whole chapter. The Sanskrit is stored by verse, and a table maps each passage onto its verses: aligned offline with a local embedding model against the gita/gita English translations, keeping verse order, then checked by hand. `read_passages` now returns only those verses, in Sanskrit and English.
- Meditations references are now one Casaubon section each (book.section) instead of a whole book. The Greek is stored by Perseus chapter, and a hand-checked table maps each of Casaubon's sections onto the chapters it translates, because his numbering merges and splits them. `read_passages` now returns only the matching section, in Greek and English.
- The keyword fallback that matches any term now ignores common English stop words, so hits no longer come in on words like "should" or "to" alone. Quoted phrases are kept, and a query made only of stop words still searches every term.
- README title renamed to Wisdom MCP, with the corpus badge first.

### Added

- Aristotle's Metaphysics (W. D. Ross, 1908), Nicomachean Ethics (D. P. Chase, 1847), Politics (William Ellis, 1776) and Rhetoric (John Henry Freese, 1926), George Long's selection from the Discourses of Epictetus with the Encheiridion (1877), C. D. Yonge's Diogenes Laertius and Letters of Epicurus (1853), the Enneads of Plotinus (Kenneth Sylvan Guthrie, 1918; Stephen MacKenna and B. S. Page, 1917–1930) and Sextus Empiricus's Outlines of Pyrrhonism (Mary Mills Patrick, 1899) can now be searched and quoted, with their Greek from Perseus canonical-greekLit or, for Plotinus and Sextus, First1KGreek. Aristotle goes by Bekker column (`1094a`, `1094b-1095a`), split at the Perseus page milestones; Diogenes Laertius, Epicurus and Sextus by book and section (`10.124`); the Discourses by chapter and the Encheiridion by section (`Ench. 5`); the Enneads by ennead, treatise and chapter (`1.6.9`). The translations are aligned in `data/alignments/<work>.json` on the Perseus or First1KGreek English translations, on Ellis's own column marks, or on Guthrie's chapter numbers, mapped onto Volkmann's where they differ, and MacKenna's scan on Guthrie. The footnotes of Ross's scan are left out by `null` anchors, and licences now credit First1KGreek for its files. Burnet's Early Greek Philosophy is left out, as its fragments have no open Greek edition. The corpus grows to 51 texts and 69,700 passages, and the retrieval test set to 88 situations.
- Plato's Euthyphro, Apology, Crito, Phaedo, Theaetetus, Symposium, Phaedrus, Alcibiades I, Protagoras, Gorgias, Meno, Republic, Timaeus and Laws (Benjamin Jowett, 1892) and the Seventh Letter (George Burges, 1851) can now be searched and quoted, with Burnet's Greek from Perseus canonical-greekLit, split at its Stephanus section milestones, speakers' labels kept and Burnet's brackets shown. The translations have no Stephanus numbers, so each is aligned in `data/alignments/<work>.json` on the section milestones of the Perseus English translation (Fowler, Lamb, Shorey, Bury), and every passage takes the sections it covers (`514a-b`, `70d-71b`). Jowett's introductions, the persons and scene of each dialogue, book heads and his note quoting Milton in the Phaedo are apparatus. The Plato files have no licence in their header, so they take the repository's CC BY-SA 4.0. The corpus grows to 41 texts and 42,448 passages, and the retrieval test set to 78 situations.
- Job, Proverbs and Psalms (King James Version, 1611) and Pirkei Avot (Joseph I. Gorfinkle, 1913) can now be searched and quoted, with their Hebrew originals from Sefaria: the Miqra according to the Masorah for the three books, as for Ecclesiastes, and Torat Emet for Pirkei Avot. Sefaria serves neither the KJV nor more than four of Gorfinkle's sayings, so the translations still come from the Wisdom Context Window. `loadSefaria` takes the work instead of hard-coding Ecclesiastes. The books go by KJV chapter and verse, mapped onto the Hebrew where the two differ: the psalm titles the Hebrew counts as verses, and Job 41:1-8, which is the Hebrew 40:25-32. Pirkei Avot goes by Gorfinkle's sayings (`2:5`), each taking the Sefaria mishnayot it falls in (`2:4`); his notes and the sayings recited before and after each chapter are apparatus. The corpus grows to 26 texts and 28,596 passages, and the retrieval test set to 63 situations.
- Bhikkhu Sujato's Core Suttas (SN 56.11, MN 10, MN 118, Snp 1.8, AN 3.65, DN 31), Sutta Nipāta, Udāna and Itivuttaka can now be searched and quoted, with their Pali originals from SuttaCentral (Mahāsaṅgīti edition). `loadSuttaCentral` takes the work and loads each of its suttas from the SuttaCentral API, one source unit per root text paragraph, with verse lines kept on lines of their own. Each passage is aligned on the bilara segments of Sujato's translation and takes that segment range as its reference (`ud1.1:2.1-2.13`); titles, chapter headings and colophons are apparatus, and the import fails on a passage it can't find in the translation. The corpus grows to 22 texts and 23,499 passages, and the retrieval test set to 59 situations.
- The Yi King (James Legge, 1882), The Art of War (Lionel Giles, 1910), The Ethical and Political Works of Motse (Yi-Pao Mei, 1929) and The Works of Hsüntze (Homer H. Dubs, 1928) can now be searched and quoted, with their Chinese originals from Chinese Wikisource. The Art of War goes by Giles's sections, each taking the source paragraphs it falls in (`6.6-7`). Mei and Dubs are scans aligned by hand on the source paragraphs in `data/alignments/<work>.json`, where a footnote runs from the first one on a page to the next page head. Legge's notes are told from his text by their longer lines; the Text goes by hexagram and the appendixes by Legge's numbering (`App. III.1.5`), on the hexagram and 易傳 pages. The I Ching readings are drafted from 周易音義, in 王弼's order; the other three have no 音義, so their polyphones take the usual reading, reviewed by hand for the Art of War and by context for some senses in the other two. The corpus grows to 18 texts and 19,440 passages, and the retrieval test set to 55 situations.
- Chuang Tzŭ (Herbert A. Giles, 1889), Taoist Teachings from the Book of Lieh Tzŭ (Lionel Giles, 1912) and The Sayings of Lao Tzŭ (Lionel Giles, 1905) can now be searched and quoted, with their Chinese originals from Chinese Wikisource. None of them has numbers or Chinese in the Wisdom Context Window, so each is aligned by hand on the source paragraphs in `data/alignments/<work>.json`: Chuang Tzŭ by chapter and paragraph (`17.12`), the Lieh Tzŭ selections by book and paragraph of the Chinese (`8.14`), and Giles's thematic sayings by the 王弼本 chapter each comes from, sharing the Legge Tao Te Ching's original and readings through a new `originalOf` on the work. A block where a unit starts midway takes a range (`10.6-7`), and its transcription joins each source unit's readings. The Zhuangzi readings are drafted from 莊子音義, whose 下同 now carries only to the phrase it names or to its headword; the Liezi readings from 殷敬順's 釋文 in the 四庫全書 edition, aligned on the text character by character. `pnpm readings:draft` takes work ids to draft only those, and fails when it misses a book heading in a 音義. The corpus grows to 14 texts and 9,986 passages, and the retrieval test set to 51 situations.
- `pnpm corpus:import --refresh` downloads the Wisdom Context Window dump again and overwrites the cached copy, which was otherwise never updated. Other cached downloads are left alone.
- `pnpm corpus:diff` downloads the latest dump, without touching the cache, and lists the full texts on the site not in `PILOT_WORKS` yet, then the imported works a re-import would change: a different number of passage blocks, or passages no longer in the block their positional id points to. It changes nothing in the database.
- The Great Learning, the Doctrine of the Mean and Mencius (James Legge) can now be searched and quoted, with their Chinese originals from Zhu Xi's 《四書章句集注》 on Chinese Wikisource. References follow Zhu Xi's chapters, as Legge's numbering does: 0–10 for the Great Learning, 1–33 for the Doctrine of the Mean, book, part and chapter for Mencius (`1A.1`). The Wisdom Context Window prints these texts with no numbers, so each translation takes the chapter its Chinese paragraph is matched to. Their polyphone readings are drafted from 集注's phonetic notes, and the corpus grows to 11 texts and 4,506 passages.
- Usage log: every MCP tool call writes a row to a new `usage` table with its time, tool, query, passage ids, hit count, duration, keyword-only fallback flag and Mistral embedding tokens (0 when the query embedding is cached). A job run at startup and every 24 hours replaces queries older than 30 days with their SHA-256 hash and keeps the other fields. The README has a new Privacy section.
- Rate limiting on `/mcp` with `@nestjs/throttler`, per client IP behind the reverse proxy: `RATE_LIMIT_PER_MINUTE` (default 30) tool calls per minute, and `SEARCH_LIMIT_PER_DAY` (default 200) `search_passages` calls per day, since each one calls Mistral. Over either limit, the endpoint answers 429 with a JSON-RPC error and `Retry-After`. Counters are kept in memory.
- Phonetic transcriptions under each original in `read_passages`, labelled as a pronunciation aid not to be quoted: Hanyu Pinyin with classical readings for Classical Chinese, romanization with accents and breathings for Ancient Greek, SBL-style romanization from the points for Biblical Hebrew, and IAST for Sanskrit. A migration adds `originals.transcription`, and `corpus:import` fills it. The `/wisdom` skill gives it after each quote.
- Pinyin for polyphones comes from committed readings files, `data/pinyin/analects.json` and `data/pinyin/tao-te-ching.json`, keyed by reference and character position. `corpus:import` fails and lists every occurrence of a classical polyphone without a reviewed reading.
- `pnpm readings:draft`: drafts those files from 《經典釋文》 (論語音義, 老子音義). It aligns each headword on the text and converts each fanqie or homophone note to pinyin through its 廣韻 sound class (ytenx), and cross-checks the Analects against 朱熹《論語集注》. An occurrence 釋文 leaves unannotated takes the usual reading (如字), except 夫 opening a clause, which is the particle fú. Of 1,892 Analects readings, 集注 confirms 274; the 169 where it disagrees, a note did not resolve, or a 下同 reached too far were reviewed by hand. The Laozi's 690 readings rest on 釋文 alone.
- `list_concepts` and `get_concept` tools over the Wisdom Context Window concept graph: 208 concepts with their summary, key passages, and parallels, tensions, related and broader concepts. `corpus:import` fetches and caches the graph into the new `concepts`, `concept_passages` and `concept_links` tables. Key passages from works in the corpus come with their passage id, and the others are listed without one. The server instructions point broad questions to the concepts before searching.
- `check_quote` tool: checks a quote against the stored originals and public-domain translations, ignoring whitespace, punctuation and section markers, and returns the exact match with its passage id, work and reference, or the closest candidates ranked by trigram overlap. An optional `work` (id, or part of its title or author) narrows the check.
- Retrieval test set in `test/eval/situations.json`: 44 situations, each with the passages judged relevant by hand, and `pnpm eval`, which runs search on each and reports Recall@10 per situation and overall. The first run scores 0.184 against a target of 0.7.
- knip, with a `pnpm knip` script and a CI step after the build, to keep unused files, exports and dependencies out of the repo.
- `docs/COMPATIBILITY.md`, a guide to the chat apps, coding tools and LLM APIs that can use the server as a connector: plans, setup per service, and how to expose the server over HTTPS. Linked from a new Compatibility section in the README.
- NestJS (ESM) project with pnpm, TypeScript, ESLint, Prettier and a CI workflow.
- SQLite database through better-sqlite3, with sqlite-vec loaded at startup and numbered SQL migrations applied on boot.
- Schema for `works`, `texts`, `passages`, `originals` and `translations`, plus the `passages_fts`, `originals_fts` and `passages_vec` indexes.
- MCP server over Streamable HTTP at `/mcp`, with host header validation and no tools yet.
- `/health` route that also checks the database.
- Swagger UI at `/docs`.
- Smoke tests for the schema, sqlite-vec, `/health` and the MCP `initialize` handshake.
- GPL-3.0 `LICENSE` file and matching `license` field in `package.json`.
- `pnpm corpus:import`, which imports the 8 pilot works (Tao Te Ching, Analects, Dhammapada, Bhagavad Gita, Enchiridion, Meditations, Sermon on the Mount, Ecclesiastes) from the Wisdom Context Window. It keeps the corpus slugs and passage numbers, and can be run again.
- Work registry with author, title, original title and language, tradition, translator, translation year and Gutenberg source.
- Normalization that rejoins hard line breaks and hyphenated words, keeps verse lines, strips italics markers and footnote anchors, and keeps the source text in `raw`.
- References in each work's own numbering. Corpus passages that hold several chapters are split, and the translators' introductions, notes, indexes and headings are flagged as apparatus.
- Original-language texts stored by reference unit, with source URL and licence, from Chinese Wikisource, Perseus, SuttaCentral, Sefaria and the gita/gita dataset. Translation units are mapped onto source units where the divisions differ.
- Downloads cached under `CORPUS_CACHE`, with retries on rate limits.
- `pnpm corpus:index`, which writes a line of modern English search keywords for each quotable passage with a Mistral model, rebuilds the FTS5 index over passage text and keywords, and embeds passages into `passages_vec` with Mistral embeddings. Keywords and embeddings are cached by passage text under `CORPUS_CACHE`, so reruns after an import cost no API calls.
- `search_passages` MCP tool: hybrid search that runs FTS5 (all terms first, then any term) and vector search, merges them with reciprocal rank fusion (k=60), keeps at most 3 hits per work and returns the top 20 with snippets. Quoted phrases are kept as phrases, and apparatus is never returned.
- Keyword-only fallback, flagged in the result, when the embedding call fails or takes longer than 5 seconds, and a 1,000-entry cache of query embeddings.
- `read_passages` MCP tool: up to 10 ids, returned as whole reference units with the original text, its source and licence, and the English translation as an aid, or the translation alone when no original is available. Output is capped at about 6,000 words, cutting the aid translation first and then the original at a sentence boundary.
- Server instructions sent at `initialize`, covering search language, quoting, translation and passages as data.
- `.mcp.json` that registers the local server with Claude Code as `wisdom`.
- `/wisdom` Claude Code skill, which answers a question and its follow-ups with `search_passages` and `read_passages` only and writes the whole conversation, with every tool call, to `test/output/` (git-ignored).
- `/wisdom` answers are a synthesis of the quoted passages only, with no advice of the model's own, with three parts: a `short_answer` (exactly yes or no for a yes/no question, otherwise one sentence), a `confidence` from 0 to 1, and a titled summary of 1 to 3 paragraphs. The transcript records `short_answer` and `confidence` in each turn and in its closing `Totals` table.
- Reframing step: the server instructions and `/wisdom` restate a question about modern specifics as the human situation underneath it before searching, while still answering the original question. `/wisdom` records the reframe under `### Reframed question`, scores `confidence` against the original question, and may run one web search to understand an unfamiliar term, never as answer content.
- `/wisdom` transcripts are numbered: `test/output/<NNNNN>-<date>-<slug>.md`, counting up from `00001`.
- `MISTRAL_API_KEY`, `EMBEDDING_MODEL` and `KEYWORDS_MODEL` settings.
- README badges for NestJS, CI, TypeScript, pnpm, Node.js and the license, plus a static corpus badge with the number of texts and passages.
- Settings load through `@nestjs/config`, which reads `.env` when it exists and validates it with zod. The corpus scripts boot a Nest application context, so they share the server's configuration.

### Fixed

- A large, small or raised letter in a Sefaria verse no longer splits its word in two, as in Ecclesiastes 7:1 and 12:13 (`ט֥ וֹב`).
- `pnpm readings:draft` placed every 音義 note after a character outside the Basic Multilingual Plane one character too far, which gave 65 Zhuangzi occurrences the wrong reading; they are redrafted.
- The Tao Te Ching `PART II.` heading is now imported as apparatus instead of a passage in chapter 37, so `read_passages` no longer appends it to that chapter's translation.
